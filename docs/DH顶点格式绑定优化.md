# DH 顶点格式绑定优化

版本：1.8.1-dh3.24。2026-09-21。

## 改动

原先 IrisLodRenderProgram 每个 VBO 调用 3 次属性启用和 3 次顶点指针设置。OpenGL 4.3+ 新路径把格式保存到程序实例私有 VAO，首次设置后只用 glBindVertexBuffer 更新绑定点 0 的缓冲地址与步长；继续保留 GL_ARRAY_BUFFER 绑定语义。

保持位置输入为 4×无符号 short 整数、颜色为 4×归一化无符号 byte、材质/法线/纹理编号为 4×无符号 byte 整数，偏移分别为 0/8/12，步长 16。三个属性均绑定点 0。

不缓存 VBO ID，每次都绑定调用者提供的缓冲，避免缓冲销毁/ID 重用问题。VAO 与原程序生命周期一致，切换光影重新创建。低于 OpenGL 4.3 使用原路径；JVM 参数 `-Doculus.dh.legacyVertexBinding=true` 可强制原路径。

## 范围与验证

不改变顶点、微偏移、索引、透明排序或绘制次数。只减少格式重复设置：稳定阶段每个 VBO 六次格式/启用调用替换为一次缓冲绑定。CPU 提交在当前高端机样本中占比小，因此不预期显著 FPS 提升，不把此改动宣称为 GPU 遮挡优化。

构建与差异检查通过，旧/新路径字段类型、归一化与步长已核对。尚未游戏内验证；需检查无光影、有光影、切换光影/维度和远近水面。重点观察先前颤动在撤除合并后是否消失。若新绑定路径异常，使用旧路径参数或恢复备份 jar。

## 其他审计结果

DH 后台已用 Future/CAS 避免并发重复上传，且主动等待上传完成以限制 staging 缓冲内存。不能简单删除 join 来宣称异步优化。其 pooled checkout 在异常路径的释放值得后续专项检查，当前未修改。

侧面合并从诊断模块的 Mixin 列表中撤下，F7 入口移除；实验源代码与记录保留。诊断模块后续版本为 0.2.1，继续使用 F8，不再提供合并开关。
