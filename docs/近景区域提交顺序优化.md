# 近景区域提交顺序优化

版本：Oculus 1.8.1-dh3.29 + dh-performance-compat 0.8.0。

## 实测依据

森林采集 `1790009998224-0df558f8` 平均 78.04 FPS。GPU 均值近景 cutout_mipped 3.875 ms、solid 3.341 ms，DH 不透明 2.266 ms，阴影总计 1.139 ms。cutout 层不等于纯树叶；阴影总计含子阶段，不能重复相加。不同阶段均值也不能强行等同整帧时间。

本轮处理近景 GPU 绘制顺序。实装 Embeddium 的 MultidrawChunkRenderBackend 仅对透明区域反向排序；普通区域沿收集顺序提交。现于 buildCommandBuffer 入口，对不透明、cutout、cutout_mipped 区域按相机到区域中心距离从近到远稳定排序，让近处深度更早建立，尝试减少后方遮挡表面的计算。

## 实现边界

- 命令生成与绘制使用同一重排列表，保留批次内容、顶点、面数、baseInstance 对应关系和视距。
- 透明混合与阴影不参与排序；检查深度测试、写深度、LESS/LEQUAL 及关闭混合状态。
- 当前仅对白名单文件名 ComplementaryReimagined_r5.8.1.zip 启用。这不是内容哈希认证，同名修改版不能视为已验证。
- 缓存区域中心坐标 MethodHandle；旧后端缺少坐标方法时绕过排序。排序暂存复用，等距离保持原顺序，非有限距离不修改列表。
- 区域中心只是启发式，原收集顺序可能已接近最优。排序及状态检查本身也有 CPU 成本，收益必须实测。
- 罕见跨区域共面材质可能受顺序影响，仍需游戏内画面验证。

## 验证与对比

两模块离线 build 通过。新增检查覆盖稳定排序、等距顺序、容量边界、NaN 输入、暂存复用及简化深度模型；Oculus 既有投影和历史矩阵检查也通过。上述检查不替代 Mixin 实际应用或复杂材质实景验证。

重启游戏加载新 jar，使用现有森林存档即可，无需新档、清缓存或重建地形：

1. 等附近加载稳定，固定位置与视角，默认开启状态按 F8 采集。
2. 采集结束后按 F6 关闭，保持位置与方向，再按 F8。
3. 可再打开补录一次，以检查时间、天气及后台负载漂移。F7 保持关闭。

F6 采集中不能切换；重启恢复默认开启，或使用 JVM 参数 `-Doculus.legacyTerrainOrder=true` 默认关闭。

F8 summary 新增 near_terrain_order、near_terrain_reordered_batches、near_terrain_reordered_regions。enabled 只表示开关状态；重排计数为零时不能声称排序实际生效。优先比较 near_solid / near_cutout_mipped GPU 时间、整帧分位数，并同时检查 CPU 是否增加。当前尚无本版本游戏内收益结论。
