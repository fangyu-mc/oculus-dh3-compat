# 按需深度快照复制

版本：Oculus dh3.30，诊断模块保持 0.8.0。

## 问题与改动

DeferredWorldRenderingPipeline.beginHand 每帧调用 RenderTargets.copyPreHandDepth，将主深度复制到 noHand（depthtex2）。原来即使没有任何着色器消费它，也执行整屏复制。当前 ComplementaryReimagined_r5.8.1.zip 的 GLSL 文件检索没有 depthtex2 引用。

IrisSamplers 现在先检查链接后的 uniform 是否存在，仅当存在 depthtex2 时请求对应纹理。RenderTargets 的公开 getter 单调记录消费需求；只要任一着色器或外部代码请求过该纹理，本管线生命周期内均保留原始复制。不依赖光影文件名白名单，编译器优化掉的未使用 uniform 也不触发需求。

仍保留首次创建及窗口尺寸/深度格式改变后的初始化复制，以及原有格式、纹理分配和资源销毁。只跳过无人消费时的后续每帧复制；depthtex1、DH 深度、手部渲染与透明阶段顺序均不变。纹理依旧分配，所以本轮不宣称降低常驻显存。

回退参数：`-Doculus.legacyDepthCopies=true`。第一次实际跳过时日志输出 `Skipping unused depthtex2 per-frame copy (no registered consumer).`，之后不逐帧刷日志。

## 验证边界

检索确认本仓库 noHand 的外部消费者只由 IrisSamplers 注册；CompositeRenderer 与 FinalPassRenderer 的图形和计算着色器均走此注册流程。getter 也为正常外部访问记录需求。任意绕过 API、直接反射读取字段的外部模组不在此契约内。

需要游戏内核对：日志证明跳过路径执行，手部、水面、透明物体、窗口 resize 及光影重载正常。首次初始化不会跳过；需要 depthtex2 的光影会自动维持复制。

这是独立的冗余带宽削减，不是森林近景片元成本的根治，也不能根据少一次 API 调用直接换算 FPS。已有 F8 不单独包围这次深度复制，因此不得将 near_cutout_mipped 时间变化直接当作本项节省量。

## 排序实验状态

dh3.29 的区域中心距离排序首次实测：开启 84.05 FPS，关闭 85.64 FPS，未证明净收益。dh3.30 默认关闭，F6 仍可显式切换，启动参数 `-Doculus.experimentalTerrainOrder=true` 可开启；legacyTerrainOrder=true 优先强制默认关闭。旧版文档中的默认开启仅描述 dh3.29。

## 首次运行采样（2026-09-22）

报告 `1790012108242-7ed7eb41`，日志确认加载 dh3.30，并于 01:33:24 输出跳过未使用 depthtex2 的提示，说明优化路径已执行。F6/F7 均关闭，计时桥接正常，GPU 查询无跳过或停止时未完成样本。

对照 dh3.29 关闭排序组 `1790011185805-0a4bb321`：

| 指标 | dh3.29 | dh3.30 |
|---|---:|---:|
| 平均 FPS | 85.64 | 84.27 |
| 平均帧时间 ms | 11.677 | 11.867 |
| P95 ms | 16.311 | 16.114 |

| 近景 solid GPU ms | 2.9586 | 3.0227 |

| 阴影总计 GPU ms | 1.0504 | 0.9642 |
| composite GPU ms | 1.8317 | 1.8330 |

未观察到整帧平均性能提升，不能用尾部小幅改善认定稳定性收益。两次跨重启，DH 每帧 draw calls 从 304 变为 310，平均索引数由 16563162 增至 16869593（约 +1.85%）；近景和阴影分段耗时也有变化，不是严格同负载 A/B，不能认定平均帧率约 -1.6% 全由本改动造成。

结论：确认去掉未消费复制的路径运行，但尚未证明可感知收益；森林近景 solid + cutout_mipped 仍约 6.57 ms，是后续重点。此项没有解决森林主要 GPU 开销；现有 F8 未单独测量深度复制，不能量化本项直接节省。
