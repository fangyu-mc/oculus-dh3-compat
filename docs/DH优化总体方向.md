# DH 优化总体方向

日期：2026-09-21  
适用环境：Minecraft 1.16.5 / Forge，DH 3.2.0-b + 自研 Oculus 兼容版。  
状态：已进入分项实装与验证；当前进度见文末，早期记录按当时状态保留。

## 一、目标

面向整合包广大玩家，从源码层面降低远景系统的 CPU、GPU、内存、显存和磁盘开销，同时提升视觉稳定性与表现力。

优先解决移动卡顿、加载尖峰和渲染错误，再提高稳定帧率与远景细节承载能力。覆盖不同档次硬件，避免优化仅对高端显卡有效。配置调低不作为源码优化成果。

## 二、总体路线

保留 DH 的数据、存储与世界生成体系，先修复现有 Oculus 接入并优化 DH 热路径，再根据实测瓶颈逐步引入批量绘制、异步上传和 GPU 遮挡等技术。

借鉴 Voxy 的技术思路，自主实现适合 1.16.5 与现有光影生态的方案。Voxy 的社区表现作为研究线索，具体收益以本整合包的对照测试为准；代码复用需符合其授权条件。

## 三、实现架构

| 落点 | 职责 |
|---|---|
| 现有 `oculus-dh-compat` | 光影接入、深度与透明通道、近远交界、渲染状态和资源生命周期 |
| 新建独立 DH 优化 mod | 性能测量、调度、缓存、上传与局部渲染优化；优先通过 DH API，其次使用局部 Mixin |
| 后续 DH fork（按需） | 深度修改网格格式、几何缓冲、绘制后端或 LOD 数据结构 |

首期采用“独立优化 mod + Mixin”，继续维护现有 Oculus fork。各项优化独立开关，方便验证和回退。

当实现需要大段覆盖核心方法、同时侵入多个生命周期，或改变数据布局与缓冲所有权时，评估转为正式 DH fork，避免长期用大量 Mixin 承载完整后端重构。届时在独立开发目录维护，`libs` 中的参考源码保持只读。

## 四、实施顺序

1. **建立基线**：确认源码与发布版本对应关系，补齐核心源码；分别测量世界生成、数据转换、构网格、上传与绘制成本。
2. **修复正确性**：处理深度、水面透明、交界过渡，以及切维度、切光影和窗口变化后的状态与资源问题。
3. **通用性能优化**：减少重复任务与过期工作，控制后台队列和资源占用，改善缓存、缓冲复用、增量更新及上传节奏。
4. **降低绘制开销**：依据测量优化逐批次提交，验证共享缓冲、批量绘制和异步上传，保留光影与事件兼容性。
5. **提高性能上限**：在收益明确时增加 GPU 层级遮挡、间接绘制和更稳定的 LOD 切换；硬件不支持时使用兼容路径。
6. **提升表现力**：改善山体轮廓、纹理闪烁、水岸与近远衔接，兼顾巨洞和特殊维度；远景阴影独立评估成本与兼容性。

阶段顺序按实测热点调整。当前逐 VBO 提交与上传尖峰是优先调查方向，尚未认定为主要瓶颈。

## 五、验收原则

- 在相同有效视距、画质和加载任务下对照，重点看帧时间长尾、加载速度和资源峰值，同时记录平均性能。
- 覆盖不同档次硬件及 AMD、NVIDIA、Intel，测试有光影与无光影两种路径。
- 覆盖静止、快速转身、高速飞行、冷缓存生成、海面、山体遮挡、巨洞与维度切换。
- 性能与视觉分别验证，再验证组合效果；收益须超过测量波动，不能靠丢细节、隐藏地形或无限延迟加载获得。
- 高级优化保留回退路径；未经实测不承诺提升倍数，不以单一机器结果代表所有玩家。

## 六、首轮范围

先完成版本与核心源码核验、性能测量、Oculus 渲染链路审计，再针对最高成本实现一个可独立验证的优化原型。根据结果决定继续局部优化，还是进入需要 DH fork 的后端重构。

本轮规划不包含 DH 大版本升级、Voxy 整体移植或数据库格式重写。

详细调研与候选方案见同目录《DH源码优化与表现力规划.md》。

## 七、首轮进展（2026-09-21）

已建立独立 `dh-performance-compat` 模块，首版提供按需 CPU 渲染采集、绘制与上传请求统计，作为对照测试入口。已依据实装 jar 的构建元数据追溯并下载对应核心子模块至 `临时/dh-core-reference`，未修改 `libs`。

当前处于诊断与验证阶段，尚未完成游戏内基线，也未启用新的优化算法。操作说明与测量边界见 `dh-performance-compat/README.md`。

## 八、回归 DH 主线（2026-09-22）

已实装标量视锥、上传失败回收、缓冲容量复用、暂存分档、构网格稳定排序及 Oculus TAA/投影兼容修复。近景区域排序首次实测未见净收益，已默认关闭；森林近景测试告一段落。

当前推进独立优化模块 0.9.0 的纹理列单向查找，保持纹理结果，削减远景数据转换的重复扫描。后续主线仍是加载吞吐、过期任务、构网格及上传生命周期，不能以静止 FPS 替代加载速度验收。说明见 ../../dh-performance-compat/docs/纹理列查找优化.md。
